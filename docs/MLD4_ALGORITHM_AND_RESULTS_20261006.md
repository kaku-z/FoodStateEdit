## 1. 任务与当前状态

目标是从一张真实食物照片生成“第一口已被勺子托起，明显离开原位置、尚未入口”的照片。输入不包含人物照片；目标图也不需要手或人物。输入实际包含 RGB 图像、可选的粗食物提示词，以及预设的取食动作参数。输出包括候选照片、编辑区域、选中材料的来源记录、三维代理几何、几何诊断和完整运行协议。

已实现的方法是：**先建立有来源索引的局部食物材料和可变形三维代理，执行一次取食动作，再让预训练图像模型受几何、来源纹理和语义共同约束地重建外观；最后对可信可见材料的内部区域恢复显式源纹理，只允许有界、平滑、无色彩的照明增益。** 最后这条显式材料通路称为 B；保留不含该投影的生成结果 A 供消融。未知表面、细边界及源缺口仍依赖生成，不能把部分可见材料的构造性约束当成完整物理守恒证明。

原 24 张统一生成实验目录为 `/host/space0/guo-z/tf-ufi/material_lineage_reform_20261004/production_head_only_20261005`，现已完成。其后在同一批输入上完成了统一 B 材料投影和独立勺柄分支的回顾性合成。另已补充真正从新 RGB 启动的单入口；开发图 02 的 v1、v2、v3 已从原始 JPEG 完整执行；24 张原始照片的 fresh 回归已于 2026-10-05 15:06 UTC 全部结束，实际耗时 33 分 47.6 秒。**这几种证据不能混为一谈：旧 24 例重放/合成不是 24 次新入口回归；单例入口跑通也不是通用成功率。** 完整摄影效果和跨图泛化仍未证明。

## 3. 从源图到三维材料动作

### 3.1 源观测与候选材料

`scripts/run_mld3.py` 接受 `--image`，对 EXIF 方向校正后的 RGB 缩放到最长边不超过 640 像素。SAM3 使用粗食物提示及通用 `food` 查询候选掩膜，按分数与面积条件选取候选；MoGe2 提供可见表面点、深度和估计内参。

原始 16+8 数据使用了源数据中的粗食物名称初始化分割和初始材料分支。代码允许默认 `food`，但初始 strand/soft/cohesive 分支的一部分逻辑依赖提示词。因此当前 24 例不应被称为完全没有元数据的自动 RGB 测试。

对观测点的平滑采用有效支持归一化：分别滤波有效点坐标的分子与有效像素权重的分母，并且仅在原本有效的位置输出；原始无效点继续保持无效。这避免 NaN 污染邻近食物点，不是对未观测深度的无依据补全。

### 3.2 连续材料先验与来源索引

MLD2 使用局部图像特征、全局图像特征、三维位置编码、源 UV 与源颜色查询连续场，输出 SDF、八个子单元中心的 SDF 辅助量及颜色修正。照片流程将其限制为局部闭合先验：保留源图中已经观测的顶面位置和颜色，对隐藏侧面、底面及厚度提出估计，并用局部尺度、最小厚度和支持面约束限制范围。

每个被搬运的材料样本保持持久 ID、源 UV、源 RGB、静止坐标和目标坐标。`transport.npz` 保存这些映射及 faces/edges；源图剩余材料与被搬运材料分别记录。隐藏纹理可能由先验或可见纹理延拓获得，必须与直接观测的源纹理区分。

这里的 `material_mass` 是固定密度和代理几何体积下的记账量；剩余像素也使用相应代理分配。没有称重数据，不能把该字段解释为真实克数或热量。

### 3.3 分支、拓扑和变形

**凝聚块/软块分支。** 从源材料顶面建立带侧面、底面的闭合局部网格。`topology.py` 保留连贯的可三角化成分，处理边界夹点，检查闭合边关联。被排除的小岛和夹点仍留在源图食物中；它们没有被隐式删除。冻结数据中 01/10/11 经过保守 packet 路由；17 做过源几何拓扑修复。

变形器使用边长弹性、图拉普拉斯弯曲、重力、闭合体积约束、弱位置约束及勺面单边接触投影。它是静态代理求解器，刚度等参数预设，并非从食物实验辨识的材料本构，也不是验证过的有限元食物模拟。

**细条分支。** 从源图的可见条状材料提取脊线和骨架路径，结合源宽度与几何形成管状代理。管面保持源纹理所有权，变形受长度、弯曲、重力、勺面接触和自碰撞约束。不可见半周使用可见材料的延拓，不能恢复盘中未观测的完整面条拓扑。

勺子是共享解析浅勺面及柄部几何：相同表面参与接触求解与渲染。抬升由局部三维动作规划控制，随后投影到图像。相对抬升可检查；绝对真实高度缺少标定依据。

新入口还在变形结束之后、PBR 渲染和阴影/guide 构建之前调用 `utensil_placement.connect_handle_to_frame`：保持勺碗及近端顶点不变，只沿柄轴以连续权重伸长远端，使柄尖投影跨出画面。该步骤改变的是三维勺柄，因此新输入只需原来的两次 Qwen 调用。开发图 02 的 v2 实跑确认柄尖由 `(350.12,73.32)` 延到 `(410,74.16)`，图宽为 400；固定的 19,604 个勺碗顶点最大位移为 0，食物 mesh/UV/IDs/颜色完全不变。它表达画外支撑的构图假设，不是实际存在一只画外手的证据。原冻结 24 例 A 不含这项上游改动；其勺柄修复使用了单独的历史分支。

## 4. MLD4 的来源约束与图像重建

### 4.1 控制图与所有权

`prepare_mld4_guides.py` 通过 z-buffer 和透视正确的重心插值，将目标食物像素映射到源 UV、材料 ID 和深度。直接可见的源顶面/相机侧管面被标记为有观测依据；隐藏底面、封口和源缺口不被标成已知纹理。

输出包括 source、coarse、edge、depth、编辑掩膜、源移除掩膜、目标食物掩膜、勺子掩膜、源材料参考和置信度。源缺口初始化使用外推，表示渲染初值，并不是隐藏盘面真值。边缘条件对外侧相通的缺口保留形状信息；内部未知空洞避免直接编码成封闭黑多边形。

后续步骤依次生成：

1. `prepare_mld4_anchors.py`：在可靠源材料区域放置确定性的稀疏颜色锚点，颜色直接来自源 UV；它们进入条件图，不是最终生成像素的硬锁。
2. `prepare_mld4_factorized.py`：把完整编辑区域划分为源缺口、勺头和柄，生成局部裁剪及相应内参；来源 UV 始终指向完整源图。
3. `prepare_mld4_dense_guides.py`：向可靠的勺头核心区域填入源 UV 纹理，并缩小局部生成条件中的未知区域；边界控制图处理不改变材料几何及最终接受掩膜。
4. `prepare_mld4_head_depth.py`：对头部物理深度做保持次序的分段归一化，以增强前后关系；未命中像素保留未知编码，不能借用抬升前食物深度伪造目标深度。

### 4.2 源语义与保守路由

`diagnose_mld4_semantics.py` 的两种模板只读取原始源图、选中区域标注和选中材料的隔离视图，不读取生成目标。`compile_mld4_captions.py` 以两次词族判断的一致性、允许的外观词及直接测量的源 RGB/Lab 编译 head/source/source_surface 文本，同时记录源文件哈希及材料所有权证据。

不一致时回退为通用食物描述，不通过人工补写配料名称修饰结果。最终 24 例中 04/10/11/18/19/23 存在语义不确定性。初始 strand 分支只有获得一致的细条语义支持才保留；否则回退凝聚材料包。重建后重新描述新的材料所有权，但不反复根据生成图改路由。

生产使用 `automatic_captions_resolved.json`；后续 `source_surface_v2` 是源支持层消融的产物，没有进入该生产协议。

### 4.3 当前生产：全图重建，再仅细化勺头

第一阶段 `run_mld4_reconstruction.py --variant owned_anchors` 使用完整源图条件、选中材料参考、稀疏来源颜色锚点和全图边缘控制生成外观。Qwen-Image-2.1 与 Fun adapter 的控制/参考组合属于工程集成，不是本项目从头训练的统一生成模型。

第二阶段 `run_mld4_factorized.py --stages head --head-control depth` 从第一阶段 `unprojected.png` 开始，在勺头裁剪内使用可靠核心的源纹理、深度控制、源材料参考和自动 head 文本细化外观。**当前协议不运行 source 局部生成阶段**。源缺口由全图阶段处理；局部阶段接受区域之外保留第一阶段结果，完整冻结编辑区域之外逐像素恢复原图。

`unprojected` 表示不启用额外的材料颜色/细节投影项，不表示未经处理的神经网络原始输出。当前合成仍包含内部边缘羽化；raw generation 和最终合成结果均需区分保存。geometry correspondence 在神经重建之后是条件证据，不能自动升级成最终像素的物理证明。

### 4.4 显式可见材料通路 B

`project_mld4_visible_material.py` 读取几何对应得到的 `material_texture`、置信度和生成提案 A。令 `known = target_food & (confidence >= 0.75)`，对 known 内部到边界至少两像素的位置设硬约束核心，其余已知边界使用固定过渡权重。在线性 RGB 中，源纹理乘由 A 与源纹理低频亮度比估计的单标量 `gain`，平滑后限制于 `[0.72,1.4]`；再转换回 sRGB。核心输出只由源纹理和该标量增益组成，不接受 A 的彩色纹理。known 外保留 A，源缺口和其他场景区域不变。

这解决的是“生成器可任意把已知橙色鱼肉改成白色材料”这一具体自由度，不能恢复不可见内部、纠正错误 UV/分割或保证摄影真实感。源 RGB 本身含原照明，因此它不是估计出的纯反射率；增益也不是实测照明。极细或不可靠区域可能没有非空硬核心，必须报告实际核心面积。

已有 `material_contract_v2/manifest.json` 记录 24/24 核心非空，共 34,102 个核心像素，核心构造误差为 0；这些是实现约束检查，不能解释成 24/24 视觉成功。默认新入口使用 B；`--free-material` 返回 A。

## 6. 算法伪代码

```text
输入：单张 RGB I，可选粗提示 p，冻结模型与动作参数
F, candidates ← SAM3(I, p 和 food)
P, K, valid ← MoGe2(I)
P ← 仅在有效支持上平滑(P, valid)
G0 ← 初始材料分支与源取食区域选择(I, F, P, K, p)
M ← 在观测表面约束下，用冻结 MLD2 建立局部材料先验(G0)
M ← 连贯拓扑切分或带源所有权的细条代理(M)
G ← 在解析勺面上执行抬升、接触与变形(M)
保持食物/勺碗固定，将远端勺柄延伸至画外
保存 source_id / source_uv / source_rgb / rest_xyz / target_xyz
C1, C2 ← 两次仅基于源图和选中材料的描述
route ← 初始分支 + 保守语义一致性决策(C1, C2)
若 route 要求凝聚包重建：
    从相同源观测重建凝聚包，重算取食材料所有权和 G
    对新所有权重新做两次源描述；不再次路由
guides ← 来源约束投影、边缘、深度、参考、锚点、局部裁剪、核心纹理
captions ← 双描述、测量颜色、来源文件哈希的保守编译
冻结 guides / captions / code / 命令 / 参数
Y0 ← Qwen 全图重建(anchors, edge, reference; CFG=3)
Y1 ← Qwen 勺头细化(Y0, dense core, depth, reference, head caption; CFG=1)
A ← 局部接受与边界合成(Y1, Y0)，冻结编辑区外严格写回 I
B ← 在可信可见材料核心内，以源 UV 纹理 × 平滑有界无色彩增益取代 A
验证 B 在冻结编辑区外仍逐像素等于 I；保留 A 作为消融
输出：B、A、原始生成、所有中间证据、几何与运行诊断
```

该执行链现由 `run_mld4_from_image.py` 串联。旧的 `run_mld4_pipeline.py` 仍只负责预计算 guides 的校验与渲染编排；必须使用新入口才会重新运行感知、几何与源语义。单入口的存在不等于任意 RGB 上都能正确选取材料或生成真实结果。

## 8. 本轮证据及其解释

已有开发例的比较显示全图阶段对部分源缺口比额外局部重建更合理，因此当前冻结协议改为全图加勺头细化。这个选择来自开发例，不能冒充独立测试集上的统计结论。

## 15. 学习先验的有效作用与剩余瓶颈

20 个非细条闭合案例中，上游记录的原始预测厚度触及固定上限的像素比例，中位数为 **85.47%**。00、01、05、10、13、15 六例的最终隐藏底面，与同一步中记录的固定厚度基线在数值误差内相同。这个诊断不是新的完整模型消融，也不证明 MLD2 对这些图的其他计算没有影响；但它说明“加载了训练模型”不能用来证明其厚度预测是必要贡献。四个细条案例的最终管体不应用该隐藏底面比较。

目前核心局限有三项。第一，源图上的高光脊线和粗分割不足以确定真实细条拓扑，搬运结果会变成宽扁带或梳齿薄片。第二，源照明已烘焙进照片纹理，显式运输保住颜色和来源，却不会自动产生新视角下自然的照明与隐藏表面。第三，当前生成器缺少与同一份材料的移除动作绑定的源区监督，常把缺口补成完整食物或其他配料。

因此，本轮结论是：**完整执行链和可见来源约束已经实现并实测，生成真实第一口的整体视觉目标尚未达标。** 下一阶段应围绕“剩余食物轮廓—新切面—被遮挡支持层”的联合建模与有针对性的配对监督建立可证伪实验，而不能把继续增加生成次数、单图好看样例或代理守恒数字当成问题已经解决。
